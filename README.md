# aibot-master

Telegram-бот с локальной нейросетью ([Ollama](https://ollama.com)). Всё работает на вашем компьютере или сервере: без облачных API, без подписок и оплаты за токены. Переписка никуда не отправляется — обрабатывается и хранится только у вас.

Собран на основе [m0wer/aibot](https://github.com/m0wer/aibot) с фичами из [mlloliveira/TelegramBot](https://github.com/mlloliveira/TelegramBot), значительно доработан.

## Возможности

**Общение**
- **Текст** — обычный чат. Ответ появляется в сообщении постепенно, по мере генерации (как в ChatGPT).
- **Фото** — пришлите картинку, бот опишет её или ответит на вопрос из подписи.
- **Голосовые** — распознаёт речь (faster-whisper) и отвечает на сказанное.
- **Документы** — пришлите PDF или текстовый файл (до 20 МБ) с вопросом в подписи, бот ответит по содержимому.
- **Поиск в интернете** — бот сам понимает, когда вопрос требует свежих данных (новости, курсы, погода), и ищет через DuckDuckGo. Есть и ручная команда `/web <запрос>`.
- **Память** — бот помнит переписку: последние сообщения видит целиком (`HISTORY_LIMIT`), а более старые автоматически сжимает в «выжимку», которую держит в уме. История не пропадает при перезапусках.
- **Персонажи** — `/persona` меняет характер бота: пират, Йода, саркастичный, учёный (список правится в `config.py`).
- **Выбор модели** — `/model`, у каждого пользователя свой выбор (подробнее ниже).
- **Группы** — бота можно добавить в групповой чат: он отвечает только на @упоминания и реплаи, у группы своя общая история.
- **Русский или английский интерфейс** — `BOT_LANGUAGE` в `.env`.

**Для владельца**
- **Ограничение доступа** — список разрешённых пользователей (`ALLOWED_USER_IDS`), чтобы ботом не пользовались чужие.
- **Защита от спама** — лимит запросов в минуту на пользователя, честная очередь с показом позиции.
- **`/stats`** — пользователи, сообщения, очередь, размер базы (видна только администратору).
- **Оповещения об ошибках** — сбои прилетают администратору личным сообщением (не чаще раза в полчаса на однотипную ошибку).
- **Резервные копии** — ежесуточный снимок базы в `data/backups/`, хранятся последние 7.
- **Healthcheck** — `docker ps` честно показывает, жив ли бот.
- **Автообновление** — опционально, см. [раздел ниже](#автообновление-watchtower).

## Требования

1. **Docker.** На Windows и macOS — [Docker Desktop](https://docs.docker.com/desktop/), на Linux — [docker engine + compose](https://docs.docker.com/engine/install/). Больше ничего ставить не нужно — Ollama установщик при необходимости поднимет сам.
2. **Токен Telegram-бота** — бесплатно за минуту: откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, придумайте имя — получите токен вида `1234567:AAE...`.
3. **Железо:** локальной модели нужна память. Для стандартной `llama3` (8B) — от 8 ГБ ОЗУ; с видеокартой NVIDIA будет сильно быстрее, но и на процессоре работает.

## Установка

**Шаг 1.** Получите токен у [@BotFather](https://t.me/BotFather) (см. выше).

**Шаг 2.** Выполните одну команду.

Linux / macOS (терминал):
```bash
curl -fsSL https://raw.githubusercontent.com/MondayDecember/aibot-master.pro/main/install.sh | bash
```

Windows (PowerShell):
```powershell
irm https://raw.githubusercontent.com/MondayDecember/aibot-master.pro/main/install.ps1 | iex
```

**Шаг 3.** Вставьте токен, когда установщик спросит. Всё остальное он сделает сам:
- проверит, что Docker установлен и запущен;
- скачает код в папку `aibot-master`;
- найдёт Ollama на вашей машине, а если её нет — запустит в docker-контейнере и скачает модели (`llama3` и `llama3.2-vision`, суммарно ~10 ГБ — это самый долгий шаг);
- соберёт и запустит бота.

**Шаг 4.** Напишите своему боту в Telegram `/start`. Готово.

Посмотреть, что происходит внутри: `docker compose logs -f bot` (из папки `aibot-master`). Остановить: `docker compose down`.

## Настройка (.env)

Все настройки — в файле `.env` в папке бота (создаётся установщиком из [.env.example](.env.example)). После изменения перезапустите бота: `docker compose up -d --build`.

**Основные:**

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | токен от @BotFather — единственное обязательное поле |
| `BOT_LANGUAGE` | язык сообщений бота: `ru` или `en` (на ответы нейросети не влияет — она отвечает на языке собеседника) |
| `OLLAMA_API_BASE` | где искать Ollama: `http://host.docker.internal:11434/v1` — на вашей машине, `http://ollama:11434/v1` — в docker-контейнере |

**Доступ и лимиты:**

| Переменная | Что делает |
|---|---|
| `ALLOWED_USER_IDS` | кто может пользоваться ботом, Telegram ID через запятую. Пусто = открыт всем. Чужому человеку бот покажет его ID — просто добавьте это число в список |
| `ADMIN_USER_ID` | кому доступна `/stats` и куда слать ошибки. По умолчанию — первый ID из списка выше |
| `RATE_LIMIT_PER_MINUTE` | сколько запросов в минуту разрешено одному человеку (по умолчанию 10, 0 = без лимита) |

**Модели:**

| Переменная | Что делает |
|---|---|
| `TEXT_MODEL` | основная текстовая модель (по умолчанию `llama3`) |
| `VISION_MODEL` | модель для картинок (по умолчанию `llama3.2-vision`) |
| `MODEL_CHOICES` | список моделей для команды `/model`, формат `имя=модель` через запятую |
| `WHISPER_MODEL` | размер модели распознавания речи: `base` (быстро) … `large-v3` (точно) |

**Память и поведение:**

| Переменная | Что делает |
|---|---|
| `HISTORY_LIMIT` | сколько последних сообщений модель видит целиком (по умолчанию 10; больше = лучше помнит, но медленнее отвечает) |
| `LONG_TERM_MEMORY` | долгая память: старые сообщения сжимаются в выжимку, которую бот всегда держит в уме (`true`/`false`) |
| `SUMMARIZE_EVERY` | как часто обновлять выжимку (каждые N сообщений, по умолчанию 20) |
| `AUTO_WEB_SEARCH` | автоматический веб-поиск. Это лишний запрос к модели перед каждым ответом — поставьте `false`, и бот будет отвечать примерно вдвое быстрее (ручной `/web` останется) |
| `STREAM_RESPONSES` | показывать ответ по мере генерации (`true`/`false`) |
| `DOC_MAX_CHARS` | сколько символов документа передавать модели (по умолчанию 12000) |
| `BACKUP_INTERVAL_HOURS` / `BACKUP_KEEP` | как часто делать бэкап базы и сколько копий хранить (24 часа / 7 копий; 0 = выключить) |

## Обновление

Вручную — две команды из папки бота:
```bash
git pull
docker compose up -d --build
```
История переписки и настройки при обновлении сохраняются (`.env` и папка `data/` не трогаются).

## Автообновление (Watchtower)

**Что это простыми словами.** Обычно, когда в этом репозитории появляется новая версия, каждый пользователь должен зайти на свой сервер и выполнить команды обновления вручную. Автообновление избавляет от этого: специальный контейнер-«сторож» (программа [Watchtower](https://containrrr.dev/watchtower/)) раз в 10 минут проверяет, не вышла ли новая версия бота, и если вышла — сам скачивает её и перезапускает бота. Вы пушите изменение на GitHub → тесты проходят → собирается образ → в течение ~10 минут все включившие эту опцию боты обновились. Без единого действия с их стороны.

**Стоит ли включать?** Да, если хотите всегда свежую версию и не хотите заходить на сервер. Нет — если предпочитаете сначала читать, что изменилось, и обновляться осознанно.

**Как включить** (2 действия):

1. В `.env` раскомментируйте строку:
   ```
   COMPOSE_FILE=docker-compose.yml:docker-compose.autoupdate.yml
   ```
   На Windows разделитель другой: `COMPOSE_FILE=docker-compose.yml;docker-compose.autoupdate.yml`
2. Перезапустите: `docker compose up -d` (именно **без** `--build`).

С этого момента бот работает из готового образа `ghcr.io/mondaydecember/aibot-master.pro` (собирается автоматически для обычных серверов и ARM, включая Raspberry Pi). База и настройки при обновлениях не трогаются. Watchtower следит **только** за контейнером бота — другие контейнеры на сервере не трогает.

**Как выключить:** закомментируйте строку `COMPOSE_FILE` обратно и выполните `docker compose up -d --build`.

## Команды бота

Команды доступны через меню по кнопке «/» в Telegram.

| Команда | Описание |
|---|---|
| `/start` | приветствие |
| `/help` | что умеет бот |
| `/clear` | очистить историю диалога (в группе — историю группы) |
| `/web <запрос>` | поиск в интернете |
| `/model` | выбрать модель (кнопками) |
| `/persona` | сменить характер бота (кнопками) |
| `/stats` | статистика — только для администратора |
| текст / фото / голосовое / документ | обрабатываются автоматически |

### Выбор модели (`/model`)

Как это устроено:

- **Владелец бота** задаёт список доступных моделей в `.env`:
  ```
  MODEL_CHOICES=default=llama3,coder=qwen3-coder:30b,big=qwen2.5:32b
  ```
  Каждая модель из списка должна быть скачана в Ollama (`ollama pull llama3` и т.д.). Если `MODEL_CHOICES` не задан, всем доступна только `TEXT_MODEL`.
- **Каждый пользователь** командой `/model` выбирает из этого списка модель **для себя**: выбор сохраняется персонально, ваш выбор не влияет на других. Кто-то общается с быстрой маленькой моделью, кто-то — с большой умной.
- Выбор действует на текст, голосовые и веб-поиск. Фото всегда анализирует `VISION_MODEL` — обычные модели картинки не понимают.

### Персонажи (`/persona`)

Готовые: `default` (обычный ассистент), `pirate`, `yoda`, `sarcastic`, `scientist` — правятся в [config.py](config.py) (словарь `PERSONAS`). Выбор тоже персональный и действует на все ответы, включая описания фото.

### Бот в группе

Добавьте бота в группу — он отвечает когда:
- его упомянули: `@имябота что думаешь?` (работает и в подписи к фото/документу);
- ответили реплаем на его сообщение.

Остальную беседу он молча читает и запоминает (история у группы общая — когда бота спрашивают, он в курсе, о чём шла речь). Личные переписки хранятся отдельно. Чтобы бот видел обычные сообщения группы, выключите у него privacy mode: в @BotFather → `/setprivacy` → Disable.

**Живое участие.** Хотите, чтобы бот вёл себя как обычный участник и иногда сам вкидывал реплики — реакцию, шутку, мнение? Включите в `.env`:
```
GROUP_CHATTINESS=10
```
Это шанс в процентах, что бот отреагирует на очередное сообщение беседы (10 = примерно каждое десятое). Чтобы бот не превращался в болтуна, действует пауза `GROUP_CHATTER_COOLDOWN` (по умолчанию 300 секунд — не чаще одной спонтанной реплики в 5 минут на чат, какой бы живой ни была беседа). Реплика короткая, в тему разговора и на языке чата. По умолчанию выключено (`0`).

## Установка вручную

Для тех, кто хочет контролировать каждый шаг:

```bash
git clone https://github.com/MondayDecember/aibot-master.pro.git aibot-master
cd aibot-master
mkdir -p data          # папка для БД - создайте ДО запуска, иначе docker создаст её от root
cp .env.example .env   # на Windows: copy .env.example .env
```

Откройте `.env`, впишите `BOT_TOKEN`. Дальше два варианта:

**Ollama уже стоит на машине** (порт 11434) — скачайте модели и запускайте:
```bash
ollama pull llama3
ollama pull llama3.2-vision
docker compose up -d --build
```

**Ollama нет** — пусть работает в докере: в `.env` установите `OLLAMA_API_BASE=http://ollama:11434/v1` и раскомментируйте `COMPOSE_PROFILES=ollama`, затем:
```bash
docker compose up -d --build
docker compose exec ollama ollama pull llama3
docker compose exec ollama ollama pull llama3.2-vision
```

В логах (`docker compose logs -f bot`) должно появиться `Database initialized`, `Connected to Redis successfully` и `Starting bot polling...`.

Если обновляетесь с очень старой версии, где база лежала в корне (`./bot_data.db`), перенесите её: `mkdir -p data && mv bot_data.db data/` (установщик делает это сам).

## Структура проекта

```
main.py                    # точка входа: бот + воркер + фоновые задачи
config.py                  # все настройки из .env
db/database.py             # SQLite: история, настройки пользователей, память
db/backup.py               # ежесуточные снимки базы
handlers/                  # aiogram-хендлеры (текст, фото, голос, документы)
middlewares/access.py      # ограничение доступа (ALLOWED_USER_IDS)
task_queue/enqueue.py      # rate limit + постановка задач в очередь
task_queue/worker.py       # воркер: разбирает очередь Redis, ходит в LLM, стримит ответ
utils/llm_client.py        # клиент Ollama + классификатор веб-поиска
utils/memory.py            # долгая память (суммаризация)
utils/group.py             # логика групповых чатов
utils/texts.py             # все тексты бота (ru/en)
utils/*_helper.py          # фото, голос, документы
utils/web_search.py        # поиск DuckDuckGo
tests/                     # автотесты (pytest)
install.sh / install.ps1   # установщики
```

## Разработка

- **Тесты:** `pip install -r requirements.txt pytest && pytest` — 25 тестов покрывают тексты, конфиг, нарезку сообщений, логику групп, rate limit, базу и бэкапы.
- **CI:** GitHub Actions на каждый пуш гоняет тесты и, только если они прошли, собирает и публикует Docker-образ (amd64 + arm64) в `ghcr.io`. Сломанный коммит не доедет до пользователей даже через автообновление.

# aibot-master

Telegram-бот с локальной нейросетью ([Ollama](https://ollama.com) или [LM Studio](https://lmstudio.ai) — любой сервер с OpenAI-совместимым API). Всё работает на вашем компьютере или сервере: без облачных API, без подписок и оплаты за токены. Переписка никуда не отправляется — обрабатывается и хранится только у вас.

Собран на основе [m0wer/aibot](https://github.com/m0wer/aibot) с фичами из [mlloliveira/TelegramBot](https://github.com/mlloliveira/TelegramBot), значительно доработан.

## Возможности

**Общение**
- **Текст** — обычный чат. Ответ появляется в сообщении постепенно, по мере генерации (как в ChatGPT).
- **Фото** — пришлите картинку, бот опишет её или ответит на вопрос из подписи.
- **Голосовые** — распознаёт речь (faster-whisper) и отвечает на сказанное. По желанию бот может отвечать на голосовые **голосом** (локальный TTS Piper, без GPU): каждый пользователь включает это себе сам кнопкой «🔊 Голосовые ответы» в `/menu` — тогда бот отвечает голосом вместо текста, без дублей. По умолчанию — текст.
- **Документы** — пришлите PDF, документ Word (`.docx`) или текстовый файл (до 20 МБ) с вопросом в подписи, бот ответит по содержимому. Кодировка текстовых файлов определяется автоматически (UTF-8, UTF-16, а также Windows-1251/ANSI — кириллица больше не превращается в кракозябры).
- **Генерация картинок** — `/imagine <описание>` рисует картинку по запросу локально (Stable Diffusion Turbo). Работает на **Windows** (CUDA для NVIDIA или DirectML для AMD/Intel) и на **Linux** (CUDA для NVIDIA или CPU) — установщики `install.ps1`/`run.ps1` и `install.sh`/`run.sh` соответственно. Отдельный сервис, запускается не через docker-compose, а сам — см. [`imagegen/README.md`](imagegen/README.md). Выключено по умолчанию (`IMAGEGEN_ENABLED`), пока не запустите сервис. Сервис слушает сеть, поэтому защитите его общим ключом: задайте одинаковый `IMAGEGEN_API_KEY` в `imagegen/.env` и в `.env` бота. Команда `/imagine` подчиняется тому же лимиту запросов, что и остальные (`RATE_LIMIT_PER_MINUTE`).
- **Поиск в интернете** — бот сам понимает, когда вопрос требует свежих данных (новости, курсы, погода), ищет через DuckDuckGo и **заходит на найденные страницы**, отвечая по их реальному содержимому, а не по коротким выдержкам из выдачи. Есть и ручная команда `/web <запрос>`.
- **Память** — бот помнит переписку: последние сообщения видит целиком (`HISTORY_LIMIT`), а более старые автоматически сжимает в «выжимку», которую держит в уме. История не пропадает при перезапусках. Выжимки может делать отдельная лёгкая модель (`SUMMARY_MODEL`) — быстрее и без выгрузки основной из памяти.
- **Напоминания** — напишите или наговорите голосовым в любой формулировке: «напомни завтра в 15:00...», «поставь заметку на 16:00...», «сделай пометку, чтоб я не забыл...» — просьба распознаётся по смыслу, бот ставит напоминание и присылает 🔔 в нужный момент. Понимает «завтра», «через 2 часа», «в пятницу» (бот сообщает модели текущую дату и время — часовой пояс задаётся `TIMEZONE`). **Повторяющиеся**: «каждый день в 9», «по будням», «каждую неделю», «каждый месяц» — бот пересоздаёт напоминание на следующий раз сам. Список и удаление: `/reminders` или кнопка в меню; явная команда: `/remind <когда и что>`. При `AUTO_WEB_SEARCH=false` распознавание по смыслу отключается вместе с классификатором — остаются ключевые слова («напомни...») и `/remind`.
- **Персонажи** — `/persona` меняет характер бота: пират, Йода, саркастичный, учёный (список правится в `config.py`).
- **Выбор модели** — `/model`, у каждого пользователя свой выбор (подробнее ниже).
- **Группы** — бота можно добавить в групповой чат: он отвечает на @упоминания и реплаи, читает и помнит беседу (общая история на чат), а при желании может и сам иногда вкидывать реплики, как обычный участник (`GROUP_CHATTINESS`).
- **Русский или английский интерфейс** — `BOT_LANGUAGE` в `.env`.

**Для владельца**
- **Ограничение доступа** — список разрешённых пользователей (`ALLOWED_USER_IDS`), чтобы ботом не пользовались чужие.
- **Защита от спама** — лимит запросов в минуту на пользователя, честная очередь с показом позиции.
- **`/stats`** — пользователи, сообщения, очередь, размер базы (видна только администратору).
- **Оповещения об ошибках** — сбои прилетают администратору личным сообщением (не чаще раза в полчаса на однотипную ошибку).
- **Резервные копии** — ежесуточный снимок базы в `data/backups/`, хранятся последние 7.
- **Healthcheck** — `docker ps` честно показывает, жив ли бот.
- **Автообновление** — опционально, см. [раздел ниже](#автообновление-watchtower).

## Требования

1. **Docker.** На Windows и macOS — [Docker Desktop](https://docs.docker.com/desktop/), на Linux — [docker engine + compose](https://docs.docker.com/engine/install/). Больше ничего ставить не нужно — Ollama установщик при необходимости поднимет сам.
2. **Токен Telegram-бота** — бесплатно за минуту: откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, придумайте имя — получите токен вида `1234567:AAE...`.
3. **Железо:** локальной модели нужна память. Для стандартной `llama3` (8B) — от 8 ГБ ОЗУ; с видеокартой NVIDIA будет сильно быстрее, но и на процессоре работает.

## Установка

**Шаг 1.** Получите токен у [@BotFather](https://t.me/BotFather) (см. выше).

**Шаг 2.** Выполните одну команду.

Linux / macOS (терминал):
```bash
curl -fsSL https://raw.githubusercontent.com/MondayDecember/aibot-master.pro/main/install.sh | bash
```

Windows (PowerShell):
```powershell
irm https://raw.githubusercontent.com/MondayDecember/aibot-master.pro/main/install.ps1 | iex
```

**Шаг 3.** Ответьте на вопросы установщика (Enter = значение по умолчанию):
- токен бота — **можно пропустить** (Enter) и ввести после установки через конфигуратор (пункт 1); до этого бот будет запущен и просто ждать токена;
- язык бота (ru/en);
- ваш Telegram ID — закроет бота от посторонних и даст вам `/stats` (узнать ID: [@userinfobot](https://t.me/userinfobot); пусто = бот открыт всем; администратором можно стать и позже командой `/admin`);
- включить ли автопоиск в интернете и автообновление;
- **какие модели скачать** — установщик сам определит объём памяти и наличие видеокарты NVIDIA и порекомендует подходящую текстовую модель (от лёгкой `llama3.2:3b` для слабых машин до `qwen2.5:32b` для мощных) и модель для анализа фото;
- **скачивать ли модели сейчас** — отдельный выбор: обе, только текстовую, только для фото, или не скачивать сейчас (бот запустится, а модели можно докачать позже командой `ollama pull`). Это самый большой объём загрузки (гигабайты), поэтому вынесен в явный вопрос.

Всё остальное установщик сделает сам:
- проверит, что Docker установлен и запущен;
- скачает код в папку `aibot-master`;
- найдёт Ollama на вашей машине, а если её нет — запустит в docker-контейнере и скачает модели (`llama3` и `llama3.2-vision`, суммарно ~10 ГБ — это самый долгий шаг);
- соберёт и запустит бота.

**Шаг 4.** Напишите своему боту в Telegram `/start`. Готово.

Посмотреть, что происходит внутри: `docker compose logs -f bot` (из папки `aibot-master`). Остановить: `docker compose down`.

## Настройка

### Конфигуратор (рекомендуемый способ)

На машине, где установлен бот, выполните из папки `aibot-master`:

```bash
bash configure.sh        # Linux/macOS
.\configure.ps1          # Windows (PowerShell)
```

Откроется меню на русском со всеми настройками и текущими значениями:

```
=== Настройки aibot-master ===
  1. Язык интерфейса бота                : ru
  2. Кто может пользоваться ботом        : 123456789
  3. Администратор (/stats и ошибки)     : (не задано)
  4. Лимит запросов в минуту на человека : 10
  ...
 14. Автообновление (Watchtower)         : выключено
  0. Сохранить и выйти
```

Вводите номер пункта, меняете значение, в конце — `0`: настройки сохранятся, и бот перезапустится сам. У каждого пункта есть подсказка, что он делает.

### Вручную (.env)

Те же настройки лежат в файле `.env` в папке бота (создаётся установщиком из [.env.example](.env.example)). После правки перезапустите бота: `docker compose up -d --build`.

**Основные:**

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | токен от @BotFather — единственное обязательное поле |
| `BOT_LANGUAGE` | язык сообщений бота: `ru` или `en` (на ответы нейросети не влияет — она отвечает на языке собеседника) |
| `OLLAMA_API_BASE` | адрес LLM-сервера (несмотря на название, подходит любой OpenAI-совместимый — Ollama, LM Studio и т.п.): `http://host.docker.internal:11434/v1` — Ollama на вашей машине, `http://ollama:11434/v1` — Ollama в docker-контейнере, `http://host.docker.internal:1234/v1` — LM Studio (порт по умолчанию 1234, не 11434) |

**Доступ и лимиты:**

| Переменная | Что делает |
|---|---|
| `ALLOWED_USER_IDS` | кто может пользоваться ботом, Telegram ID через запятую. Пусто = открыт всем. Чужому человеку бот покажет его ID — просто добавьте это число в список |
| `ADMIN_USER_ID` | кому доступна `/stats` и куда слать ошибки. По умолчанию — первый ID из списка выше. Если при установке ID не указывали — просто отправьте боту `/admin`: пока администратора нет, команда назначит вас |
| `RATE_LIMIT_PER_MINUTE` | сколько запросов в минуту разрешено одному человеку (по умолчанию 10, 0 = без лимита) |

**Модели:**

| Переменная | Что делает |
|---|---|
| `TEXT_MODEL` | основная текстовая модель (по умолчанию `llama3`) |
| `VISION_MODEL` | модель для картинок (по умолчанию `llama3.2-vision`) |
| `MODEL_CHOICES` | список моделей для команды `/model`, формат `имя=модель` через запятую |
| `WHISPER_MODEL` | размер модели распознавания речи: `base` (быстро) … `large-v3` (точно) |

**Память и поведение:**

| Переменная | Что делает |
|---|---|
| `HISTORY_LIMIT` | сколько последних сообщений **бот отправляет** модели (по умолчанию 10) |
| `MODEL_NUM_CTX` | размер **контекстного окна модели** в токенах. У Ollama по умолчанию всего 2048/4096 — она молча забывает старое; поднимите (напр. 8192), чтобы реально помнила больше. 0 = дефолт модели |
| `SHOW_TOKENS` | показывать счётчик токенов под ответом (`true`/`false`) |
| `LONG_TERM_MEMORY` | долгая память: старые сообщения сжимаются в выжимку, которую бот всегда держит в уме (`true`/`false`) |
| `SUMMARIZE_EVERY` | как часто обновлять выжимку (каждые N сообщений, по умолчанию 20) |
| `SUMMARY_MODEL` | отдельная модель для выжимок и разбора напоминаний (пусто = основная; лёгкая `llama3.2:3b` заметно быстрее) |
| `TIMEZONE` | часовой пояс для напоминаний и «чувства времени» бота (например `Europe/Moscow`, `Asia/Tomsk`) |
| `AUTO_WEB_SEARCH` | автоматический веб-поиск. Это лишний запрос к модели перед каждым ответом — поставьте `false`, и бот будет отвечать примерно вдвое быстрее (ручной `/web` останется) |
| `WEB_FETCH_PAGES` / `WEB_PAGE_MAX_CHARS` | «глубокий» поиск: сколько страниц из выдачи открывать и сколько текста читать с каждой (2 страницы × 2000 символов; 0 = только выдержки из выдачи). Большие значения требуют модель с большим контекстным окном |
| `STREAM_RESPONSES` | показывать ответ по мере генерации (`true`/`false`) |
| `DOC_MAX_CHARS` | сколько символов документа передавать модели (по умолчанию 12000) |
| `GROUP_CHATTINESS` / `GROUP_CHATTER_COOLDOWN` | «живое участие» в группах: шанс в % вкинуть реплику без обращения (0 = выключено) и минимальная пауза между такими репликами (300 с) |
| `BACKUP_INTERVAL_HOURS` / `BACKUP_KEEP` | как часто делать бэкап базы и сколько копий хранить (24 часа / 7 копий; 0 = выключить) |

## Меню управления

Запустите установщик повторно из папки бота — вместо новой установки откроется текстовое меню:

```bash
bash install.sh        # Linux/macOS
.\install.ps1          # Windows
```

```
=== aibot-master — бот уже установлен ===
  1) Обновить (забрать новую версию и перезапустить)
  2) Переустановить (пересобрать контейнеры, настройки сохранить)
  3) Сменить токен бота Telegram
  4) Изменить настройки (язык, доступ, модели...)
  5) Удалить ПОЛНОСТЬЮ (стереть бота и ВСЕ данные — безвозвратно)
  0) Выход
```

Обновление и переустановка сохраняют историю и настройки. **Пункт 5 полностью удаляет бота** — контейнеры, docker-образ, историю диалогов, напоминания, настройки (`.env`) и резервные копии; при желании — и саму папку программы. Действие безвозвратно, поэтому требует ввести слово `delete` для подтверждения. Скачанные модели Ollama по умолчанию **не удаляются** (чтобы не качать заново гигабайты) — их стирание предлагается отдельным вопросом. Саму программу Ollama установщик не трогает: если она стоит на хосте, остаётся на месте; в docker удаляется только её контейнер.

Обновиться можно и вручную, двумя командами из папки бота:
```bash
git pull
docker compose up -d --build
```
История переписки и настройки при обновлении сохраняются (`.env` и папка `data/` не трогаются).

## Автообновление (Watchtower)

**Что это простыми словами.** Обычно, когда в этом репозитории появляется новая версия, каждый пользователь должен зайти на свой сервер и выполнить команды обновления вручную. Автообновление избавляет от этого: специальный контейнер-«сторож» (программа [Watchtower](https://containrrr.dev/watchtower/)) раз в 10 минут проверяет, не вышла ли новая версия бота, и если вышла — сам скачивает её и перезапускает бота. Вы пушите изменение на GitHub → тесты проходят → собирается образ → в течение ~10 минут все включившие эту опцию боты обновились. Без единого действия с их стороны.

**Стоит ли включать?** Да, если хотите всегда свежую версию и не хотите заходить на сервер. Нет — если предпочитаете сначала читать, что изменилось, и обновляться осознанно.

**Как включить:** проще всего — пункт «Автообновление (Watchtower)» в [конфигураторе](#конфигуратор-рекомендуемый-способ) или ответ «y» на вопрос установщика. Вручную — 2 действия:

1. В `.env` раскомментируйте строку:
   ```
   COMPOSE_FILE=docker-compose.yml:docker-compose.autoupdate.yml
   ```
   На Windows разделитель другой: `COMPOSE_FILE=docker-compose.yml;docker-compose.autoupdate.yml`
2. Перезапустите: `docker compose up -d` (именно **без** `--build`).

С этого момента бот работает из готового образа `ghcr.io/mondaydecember/aibot-master.pro` (собирается автоматически для обычных серверов и ARM, включая Raspberry Pi). База и настройки при обновлениях не трогаются. Watchtower следит **только** за контейнером бота — другие контейнеры на сервере не трогает.

**Как выключить:** закомментируйте строку `COMPOSE_FILE` обратно и выполните `docker compose up -d --build`.

## Команды бота

Команды доступны через меню по кнопке «/» в Telegram.

| Команда | Описание |
|---|---|
| `/start` | приветствие |
| `/help` | что умеет бот |
| `/new` | начать новый диалог (сбросить контекст, историю сохранить) |
| `/summary` | краткое содержание текущего диалога |
| `/clear` | очистить историю диалога (в группе — историю группы) |
| `/web <запрос>` | поиск в интернете |
| `/remind <когда и что>` | поставить напоминание (или просто «напомни...» текстом/голосом); поддерживает повторы |
| `/reminders` | список напоминаний с удалением (🔁 = повторяющееся) |
| `/model` | выбрать модель (кнопками) |
| `/persona` | сменить характер бота (кнопками) |
| `/setprompt <текст>` | личные инструкции (custom instructions); `/setprompt` — показать, `/setprompt -` — убрать |
| `/language` | язык интерфейса (ru/en), персонально для каждого |
| `/whoami` | ваш Telegram ID и текущие настройки |
| `/dice` | кубик / монетка / случайный выбор: `/dice`, `/dice 20`, `/dice монетка`, `/dice кофе, чай` |
| `/roll <нотация>` | бросок кубиков: `/roll 2d6`, `/roll d20+3` |
| `/8ball` | магический шар (случайный ответ) |
| `/stats` | статистика — только для администратора |
| `/usage` | журнал обращений к нейросети: когда и сколько токенов (админ) |
| `/admin` | стать администратором (если он не был назначен при установке) или передать права: `/admin <id>` |
| текст / фото / голосовое / документ | обрабатываются автоматически |

Под ответами бота есть кнопки **↻ Другой ответ** (перегенерировать), **🔊 Озвучить** (получить ответ голосом) и, пока идёт генерация, **⏹ Остановить**. Длинные блоки кода приходят с кнопкой «Копировать».

### Выбор модели (`/model`)

Как это устроено:

- **Владелец бота** задаёт список доступных моделей в `.env`:
  ```
  MODEL_CHOICES=default=llama3,coder=qwen3-coder:30b,big=qwen2.5:32b
  ```
  Каждая модель из списка должна быть скачана в Ollama (`ollama pull llama3` и т.д.). Если `MODEL_CHOICES` не задан, всем доступна только `TEXT_MODEL`.
- **Каждый пользователь** командой `/model` выбирает из этого списка модель **для себя**: выбор сохраняется персонально, ваш выбор не влияет на других. Кто-то общается с быстрой маленькой моделью, кто-то — с большой умной.
- Выбор действует на текст, голосовые и веб-поиск. Фото всегда анализирует `VISION_MODEL` — обычные модели картинки не понимают.

### Персонажи (`/persona`)

Готовые: `default` (обычный ассистент), `coder` (💻 профессиональные ответы по программированию — код в блоках, комментарии, best practices), `pirate`, `yoda`, `sarcastic`, `scientist` — правятся в [config.py](config.py) (словарь `PERSONAS`). Выбор тоже персональный и действует на все ответы, включая описания фото.

### Бот в группе

Добавьте бота в группу — он отвечает когда:
- его упомянули: `@имябота что думаешь?` (работает и в подписи к фото/документу);
- ответили реплаем на его сообщение.

Остальную беседу он молча читает и запоминает (история у группы общая — когда бота спрашивают, он в курсе, о чём шла речь). Личные переписки хранятся отдельно. Чтобы бот видел обычные сообщения группы, выключите у него privacy mode: в @BotFather → `/setprivacy` → Disable.

**Живое участие.** Хотите, чтобы бот вёл себя как обычный участник и иногда сам вкидывал реплики — реакцию, шутку, мнение? Включите в `.env`:
```
GROUP_CHATTINESS=10
```
Это шанс в процентах, что бот отреагирует на очередное сообщение беседы (10 = примерно каждое десятое). Чтобы бот не превращался в болтуна, действует пауза `GROUP_CHATTER_COOLDOWN` (по умолчанию 300 секунд — не чаще одной спонтанной реплики в 5 минут на чат, какой бы живой ни была беседа). Реплика короткая, в тему разговора и на языке чата. По умолчанию выключено (`0`).

## Установка вручную

Для тех, кто хочет контролировать каждый шаг:

```bash
git clone https://github.com/MondayDecember/aibot-master.pro.git aibot-master
cd aibot-master
mkdir -p data          # папка для БД - создайте ДО запуска, иначе docker создаст её от root
cp .env.example .env   # на Windows: copy .env.example .env
```

Откройте `.env`, впишите `BOT_TOKEN`. Дальше два варианта:

**Ollama уже стоит на машине** (порт 11434) — скачайте модели и запускайте:
```bash
ollama pull llama3
ollama pull llama3.2-vision
docker compose up -d --build
```

**Ollama нет** — пусть работает в докере: в `.env` установите `OLLAMA_API_BASE=http://ollama:11434/v1` и раскомментируйте `COMPOSE_PROFILES=ollama`, затем:
```bash
docker compose up -d --build
docker compose exec ollama ollama pull llama3
docker compose exec ollama ollama pull llama3.2-vision
```

В логах (`docker compose logs -f bot`) должно появиться `Database initialized`, `Connected to Redis successfully` и `Starting bot polling...`.

Если обновляетесь с очень старой версии, где база лежала в корне (`./bot_data.db`), перенесите её: `mkdir -p data && mv bot_data.db data/` (установщик делает это сам).

## Разработка

- **Тесты:** `pip install -r requirements.txt pytest && pytest` — 40 тестов: юнит (тексты и полнота переводов, конфиг, нарезка сообщений, логика групп и «живого участия», rate limit, база, бэкапы, конфигуратор), интеграционные (весь конвейер воркера от очереди до ответа на фейках) и тесты-«сторожа» (каждая настройка кода задокументирована в `.env.example`).
- **CI:** GitHub Actions на каждый пуш гоняет тесты и валидирует docker-compose файлы (включая overlay автообновления), и только если всё прошло — собирает и публикует Docker-образ (amd64 + arm64) в `ghcr.io`. Сломанный коммит не доедет до пользователей даже через автообновление.
